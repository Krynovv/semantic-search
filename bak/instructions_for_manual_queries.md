# Инструкция: Как писать ручные запросы на русском

## Цель

Создать **50–100 реалистичных запросов на русском языке** для поиска Python-функций из тестового корпуса. Эти запросы нужны, чтобы проверить качество семантического поиска на настоящих русскоязычных формулировках (не машинный перевод).

## Откуда брать функции

Пул функций: `kursovaya-tex/results/manual_pool.md` — 150 функций из CodeSearchNet (test-сплит). Для каждой функции показаны:
- ID (например, `test-1234`)
- Сигнатура (`def function_name(args)`)
- Первые 3–5 строк кода (без docstring — он удалён)
- URL на GitHub (можно открыть полный код, если первых строк недостаточно)

**Выбирай функции, которые:**
- Понятны из названия и первых строк (не нужно читать весь проект)
- Решают конкретную задачу (не абстрактные обёртки вроде `def wrapper(*args)`)
- Разнообразны по типам: валидация, парсинг, конверсия, математика, работа с файлами, HTTP, и т.д.

**Пропускай:**
- Слишком простые (одна строка `return x > 0`)
- Непонятные без контекста проекта (внутренние хелперы фреймворков)
- Те, где код содержит только `pass`, `raise NotImplementedError` или декораторы

## Как писать запрос

**Формат:** естественный русский язык, 5–20 слов.

**Главное правило:** пиши запрос **как пользователь**, который ищет функцию для своей задачи, НЕ глядя на docstring (его нет).

### Что хорошо

✅ **Описание задачи:**
- «найти максимальный элемент в списке»
- «проверить, является ли строка валидным email»
- «преобразовать словарь в JSON-строку»

✅ **Конкретное действие + объект:**
- «прочитать файл построчно и убрать пробелы»
- «отправить POST-запрос с JSON-данными»
- «вычислить MD5-хэш строки»

✅ **Вопросительная форма (естественно):**
- «как извлечь число из строки»
- «как отсортировать список по длине элементов»

### Что плохо

❌ **Копирование docstring** (даже если ты его видел на GitHub):
- «Return the maximum element from a list» → слишком близко к оригиналу

❌ **Слишком общий запрос:**
- «обработать данные» — какие данные? как обработать?

❌ **Слишком технический (как в документации):**
- «реализация алгоритма Дейкстры для взвешенного графа» — если функция не называется `dijkstra`, пользователь так не ищет

❌ **Использование имени функции или параметров из кода:**
- «функция validate_email_address для проверки» — имя функции уже подсказка

## Примеры

### 1. Функция: `def is_prime(n)`

✅ Хорошие: «проверить, является ли число простым», «определить простое число или составное»
❌ Плохие: «функция is_prime» (имя в запросе), «проверка числа» (слишком общо)

### 2. Функция: `def parse_json_file(path)`

✅ Хорошие: «прочитать JSON из файла», «загрузить данные из JSON-файла»
❌ Плохие: «parse JSON file» (английский), «открыть файл» (слишком общо)

### 3. Функция: `def mappable(obj)` (проверяет, можно ли применить map)

✅ Хорошие: «проверить, можно ли применить map к объекту», «является ли объект итерируемым для map»
❌ Плохие: «mappable» (имя функции), «проверить тип объекта» (слишком общо)

## Формат результата

Файл: `kursovaya-tex/results/manual_queries.jsonl` (JSON Lines, по одной строке на запрос).

Структура строки:
```json
{"id": "test-1234", "query_ru": "проверить, является ли число простым"}
```

- `id` — точный ID из `manual_pool.md` (например, `test-20659`)
- `query_ru` — твой запрос на русском (5–20 слов)

## Как сдавать

1. Выбери 50–100 функций из пула (не обязательно первые по порядку).
2. Напиши запрос к каждой, следуя правилам выше.
3. Сохрани в `kursovaya-tex/results/manual_queries.jsonl`.
4. Проверь формат:
   ```bash
   cd kursovaya-tex/code
   .venv/bin/python -c "import json; [json.loads(line) for line in open('../results/manual_queries.jsonl')]"
   ```

## Сколько нужно

Минимум: **50 запросов** (для статистической значимости).
Рекомендуется: **100 запросов** (более устойчивые метрики).
