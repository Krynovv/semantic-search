## Шаг 3 — Дообучение multilingual-e5-base

Статус: **код и ноутбук готовы, обучение в Colab ещё не выполнено** (результаты ниже — заглушки,
заполняются после прогона `notebooks/train_colab.ipynb`).

### Что нужно получить

Планка — e5-base без дообучения на тесте n=1000 (`results/step2-rerun-report.md`):

| модель | EN MRR@10 | RU MRR@10 | ручные, n=57 MRR@10 |
|---|---:|---:|---:|
| e5-base (без дообучения) | 0.7575 | 0.5256 | 0.8847 |

Дообученная модель должна **обогнать 0.5256 на русских запросах** ценой потери на
английских не больше нескольких сотых (иначе дообучение «забудет» EN — как раз это
и показывает `mix-en`). Ожидание из плана — +0.10–0.15 MRR на RU.

Эксперименты (оба: `MultipleNegativesRankingLoss`, in-batch негативы, batch 32, lr 1e-5,
3 эпохи → 9375 шагов, одинаковые для честного сравнения):

- **`ru-only`** — 100k пар `query_ru` (NLLB) → код;
- **`mix-en`** — 50k пар `query_ru` → код + 50k пар `query_en` → код (те же коды).

### Как запустить

#### Локально (проверка без обучения)

```bash
cd kursovaya-tex/code
.venv/bin/python -m pytest tests/test_train.py -v
.venv/bin/ruff check . && .venv/bin/mypy --explicit-package-bases

# оценка уже готовой модели (после Colab): ~1 ч на CPU на 5000 функций
.venv/bin/python -m semsearch.train_cli evaluate --model <каталог/модели>
```

#### В Colab

1. Runtime → Change runtime type → **T4 GPU**.
2. Положить на Google Drive в `semsearch_step3/data/`: `train_with_ru.jsonl`,
   `test_pool.jsonl`, `test_queries_nllb_ru_1000.jsonl` (из `code/var/data/`) и
   `manual_queries.jsonl` (из `results/`).
3. Открыть `notebooks/train_colab.ipynb`, выполнить ячейки по порядку. Ячейка
   «Скорость GPU» печатает прогноз времени: если больше ~4 ч — брать L4/ночную сессию
   или `epochs=2`.
4. Забрать с Drive `semsearch_step3/out/`: `train_log_ru-only.csv`,
   `train_log_mix-en.csv`, `metrics_ru-only.json`, `metrics_mix-en.json`, каталоги

### Решения и почему

1. **Обучение только в Colab.** На локальной машине обучение обрывается через несколько
   минут (research-log 2026-11-23). Причина найдена: системный `earlyoom` шлёт SIGTERM
   процессу (RSS ~4.9 ГБ) при `mem available` ≤ 10% и `swap free` ≤ 10% — на машине 16 ГБ RAM,
   swap (zram) почти целиком занят сторонними приложениями. Обрыв воспроизводится и на
   штатном `SentenceTransformerTrainer` с 10 парами, и на нашем коде — это не ошибка в коде,
   а нехватка памяти. Поэтому локально — данные, тесты и оценка, обучение — на T4.
   Отладка обучения на GPU не нужна отдельно: ноутбук вызывает тот же `train_finetune`.
2. **`MultipleNegativesRankingLoss`.** In-batch негативы — стандарт для retrieval;
   батч 32 даёт 31 негатив на пару бесплатно. Пары перемешиваются (`to_dataset`): для
   `mix-en` иначе EN- и RU-пара одного кода оказываются в одном батче, и правильный
   ответ штрафуется как негатив. Фильтр дублей (`NO_DUPLICATES`) при этом не нужен:
   повторяющихся пар в датасете нет.
3. **`mix-en` — 50k+50k, а не 100k+100k.** Иначе у `mix-en` вдвое больше пар и шагов, и
   любое преимущество нельзя отнести к языку, а не к количеству шагов.
4. **Префиксы e5 добавляются в тексты** (`to_dataset`). В sentence-transformers 6.3
   `MultipleNegativesRankingLoss` не принимает `query_prefix`/`passage_prefix`; префиксы
   должны совпадать с `EvalConfig`, поэтому берутся из него.
5. **Своя оценка внутри обучения** — тот же `Embedder`+`DenseIndex`+`evaluate`, что у
   baseline'ов, а не `InformationRetrievalEvaluator` из библиотеки: метрики «до» и «после»
   должны считаться одинаково.
6. **Карточка модели отключена** (`_Trainer`). Штатный тренер при каждом сохранении
   кодирует примеры по одному ради README — минуты на чекпоинт; модель сохраняется тем же
   `save_pretrained(create_model_card=False)` и остаётся читаемой `SentenceTransformer`.

### Открытые вопросы и риски

- **Время на T4.** 9375 шагов × 2 эксперимента; ячейка «Скорость GPU» меряет скорость до запуска. Если
  не влезает в сессию — чекпоинты каждые 1000 шагов позволяют продолжить.
- **Оценка во время обучения стоит времени** (индекс 5000 функций на каждый `EVAL_EVERY`).
  На T4 это секунды, итоговый прогон `evaluate` — минуты.
- **Локальный прогон `train_finetune` не доведён до конца** из-за `earlyoom`: процесс
  убит примерно через 4.5 мин, успев записать только строку `step=0`, не дойдя до шага 4.
  Полный путь (шаг → лог → чекпоинт → сохранение модели) впервые пройдёт в Colab;
  локально проверены оценка (baseline воспроизведён), подготовка данных, сборка
  train-аргументов и `save_pretrained` (загруженная модель даёт те же эмбеддинги).
- **Отладочный `limit`** (прогон на 1000 парах) в ноутбук не включён: метрики на малой
  выборке не сопоставимы с полным прогоном.
