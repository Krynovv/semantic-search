## Шаг 2 — Baseline

Дата прогона: 2026-11-22. Окружение: Arch Linux, CPU 8 ядер, без GPU, Python 3.12.15 (`.venv`).

### Что считается

- **Корпус:** `test_pool.jsonl` — **5000 функций** (test-сплит CodeSearchNet, docstring удалён в Шаге 1).
- **Глубина выдачи:** 10 → MRR@10, Recall@1/5/10, nDCG@10.
- **Запросы:** 200 из `test_queries.jsonl` (первые 200 по порядку файла). RU-варианты
  переведены **NLLB-600M** — EN→RU и RU→EN — специально для этого шага
  (`var/data/step2/`, см. DECISIONS §15). EN считается **на тех же 200 id**, иначе
  сравнение EN/RU было бы на разных наборах.
- **Почему 200, а не 1000:** на диске были только 200 RU-переводов (кэш Шага 1
  локального прогона с `--limit 200`, причём от opus-mt). Полные 1000 RU-переводов
  NLLB должны прийти из Colab (ноутбук `translate_nllb.ipynb`). В отчёте этот набор
  помечен как **RU(translated, n=200)**.

### Сделано

| файл | что внутри |
|---|---|
| `semsearch/core/chunk.py` | `CodeChunk(id, code)` — документ индекса |
| `semsearch/core/index_lexical.py` | BM25 по коду: токенизация `snake_case`/`camelCase` (`XMLParser` → `xml`, `parser`), `build` / `search` / `search_many` / `save` / `load` |
| `semsearch/core/index_dense.py` | `Embedder` (multilingual-e5-base, префиксы `query: ` / `passage: `, L2-нормировка) + FAISS `IndexFlatIP`; `build` / `search` / `save` / `load` |
| `semsearch/core/metrics.py` | `reciprocal_rank`, `recall_at_k`, `ndcg_at_k`, `evaluate` (средние по запросам) |
| `semsearch/eval/run_eval.py` | сборка языковых наборов, прогон обоих индексов, запись `results/baselines.csv` |
| `tests/test_metrics.py` | метрики на ручных примерах с известным ответом (позиции 1, 2, 5, промах) |
| `tests/test_index_lexical.py` | токенизация, граничные случаи, build → save → load даёт ту же выдачу |
| `tests/test_index_dense.py` | то же для FAISS (эмбеддер подменён мешком слов, модель не грузится) |
| `tests/test_run_eval.py` | EN и RU считаются на одних id; неполный RU не ломает EN |

Решения — `code/DECISIONS.md` §12–§17: сохранение индексов, префиксы e5 и IndexFlatIP,
«ответ за пределами выдачи = промах» (а не исключение), источник RU-переводов,
добавленные зависимости, статус ручных запросов.

### Как запустить

Все команды — из `kursovaya-tex/code`, окружение — `.venv`.

```bash
# 0) один раз: зависимости (в requirements.txt уже зафиксированы)
uv pip install --python .venv/bin/python torch --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv/bin/python -r requirements.txt

# 1) RU-переводы NLLB-600M, EN→RU и RU→EN (если готовых файлов нет)
.venv/bin/python -m semsearch.data.translate \
  --input var/data/step2/test_queries_200en.jsonl \
  --output var/data/step2/test_200_nllb_ru.jsonl \
  --field query_en --out-field query_ru --direction nllb-en2ru --device cpu
.venv/bin/python -m semsearch.data.translate \
  --input var/data/step2/test_200_nllb_ru.jsonl \
  --output var/data/step2/test_200_nllb_ru_en.jsonl \
  --field query_ru --out-field query_en_back --direction nllb-ru2en --device cpu
# ~10 мин ЕN→RU и ~15 мин RU→EN на CPU (0,33 и 0,23 запроса/с), модель 2,5 ГБ

# 2) baseline: оба метода, все языковые варианты → results/baselines.csv
.venv/bin/python -m semsearch.eval.run_eval --method all \
  --ru-queries var/data/step2/test_200_nllb_ru.jsonl \
  --back-queries var/data/step2/test_200_nllb_ru_en.jsonl \
  --output ../results/baselines.csv
# BM25 — ~15 с, e5 на CPU — ~30 мин (индексирование 5000 функций × 512 токенов)

# 3) отладочный прогон (задание: --limit 1000): EN на 1000 запросах, без RU
.venv/bin/python -m semsearch.eval.run_eval --method all --limit 1000

# 4) только BM25 (секунды), только e5
.venv/bin/python -m semsearch.eval.run_eval --method bm25
.venv/bin/python -m semsearch.eval.run_eval --method dense

# 5) проверки
.venv/bin/python -m pytest
.venv/bin/python -m ruff check .
.venv/bin/python -m mypy --explicit-package-bases
```

### Результаты

Тест-корпус 5000 функций, глубина 10. `results/baselines.csv` (utf-8-sig):

| метод | запросы | n | MRR@10 | Recall@1 | Recall@5 | Recall@10 | nDCG@10 |
|---|---|---|---:|---:|---:|---:|---:|
| BM25 | EN (docstring) | 200 | 0.5427 | 0.4700 | 0.6550 | 0.6900 | 0.5784 |
| BM25 | RU(translated) | 200 | 0.2137 | 0.1700 | 0.2700 | 0.3150 | 0.2378 |
| BM25 | RU→EN (`+mt_en`) | 200 | 0.3793 | 0.3100 | 0.4700 | 0.5200 | 0.4133 |
| e5-base | EN (docstring) | 200 | **0.7545** | **0.6750** | **0.8650** | **0.8850** | **0.7868** |
| e5-base | RU(translated) | 200 | **0.5384** | **0.4600** | **0.6450** | **0.7000** | **0.5773** |
| BM25 | RU(manual) | 10 | 0.1200 | 0.1000 | 0.2000 | 0.2000 | 0.1387 |
| e5-base | RU(manual) | 10 | 0.9500 | 0.9000 | 1.0000 | 1.0000 | 0.9631 |

Воспроизведение — команда 2 из списка выше; числа в таблице и в csv совпадают
(сверено после финального прогона).

#### Выводы по методам

- **e5-base без дообучения — сильная база.** На EN он даёт MRR@10 0.7545 против 0.5427
  у BM25 (+0,21), Recall@10 0.885 против 0.690. Это и есть «планка», которую должна
  побить (или хотя бы сравняться с ней по русскому) дообученная модель из Шага 3.
- **Русский запрос без перевода BM25 почти не находит:** MRR@10 0.2137, Recall@10 0.3150 —
  из 200 запросов ответ попал в первые 10 лишь у 63. Ненулевое значение объяснимо:
  docstring-«запрос» часто содержит имена вроде `S3`, `TextGrid`, `Praat`, `exact match`,
  которые NLLB оставил латиницей, плюс в корпус попадают числа и имена функций.
  Это нижняя граница, как и ожидалось в задании.
- **Перевод RU→EN восстанавливает BM25:** 0.2137 → 0.3793 MRR@10 (+0,17), попадания
  63 → 104 из 200. Но до BM25 на родном английском (0.5427) не дотягивает — потери
  перевода никуда не исчезают.
- **Круговое переводит BM25 по RU→EN — верхняя оценка** (DECISIONS §8): перевод делал
  тот же NLLB, что EN→RU, поэтому термины и порядок слов ближе к оригиналу, чем у
  независимого русского запроса. Разница «RU как есть → RU→EN» скорее занижена, чем
  завышена, но абсолютное число 0.3793 — не честное измерение для гибрида.
- **e5 переносит русский без перевода заметно лучше:** MRR@10 0.5384 против 0.2137
  у BM25 (+0,32) и 0.7000 Recall@10 — ответ находится у 140 запросов из 200.
  До EN-качества (0.7545) он не дотягивает, это и есть задел для дообучения (Шаг 3).
- **По сравнению с гибридом-предпосылкой:** на RU e5 (0.5384) уже выше BM25 по
  RU→EN (0.3793). Значит, выигрыш гибрида из Шага 4 будет измеряться главным
  образом против e5 без дообучения, а BM25 по переведённому запросу будет
  добавлять то, что e5 теряет (редкие идентификаторы, точные имена).
- **RU(manual, n=10) — предварительно, в выводы не берётся.** e5 0.95 и BM25 0.12
  на 10 запросах: один промах меняет MRR на 0,1, доверительных интервалов нет
  (они — Шаг 4), а запросы писались автором, уже видя функцию. Совпадение релевантных
  id у `manual` и у EN/RU при этом не случайно: руками выбирались конкретные функции
  пула — это тоже причина интерпретировать цифру осторожно.

#### Что нужно разобрать перед защитой

- Почему BM25 на коде требует разбиения `snake_case`/`camelCase` и что было бы без него
  (тест `test_tokenize_splits_*` — минимальный ответ).
- Зачем e5 префиксы `query: ` / `passage: ` и почему эмбеддинги нормируются
  (IndexFlatIP = косинус).
- Почему «ответ не в выдаче» — это 0, а не ошибка, и как из-за этого первая версия
  «падала на BM25 по-русски».
- Почему EN и RU считаются на одних и тех же 200 id и чем это грозит (сдвиг EN-метрик
  относительно полного набора 1000 запросов).

### Проблемы/вопросы

1. **RU-метрики только на n=200.** На диске нет полных NLLB-переводов 1000 запросов.
   Нужно скачать `nllb_translation_results.zip` из Colab и повторить команду 2 —
   код менять не придётся (EN и RU на одном наборе, `--limit` не нужен).
2. **Файлы Шага 1 — от opus-mt, а не NLLB.** `var/data/test_queries_ru.jsonl` и
   `test_queries_en_back.jsonl`: 195 из 200 запросов найдены в кэше
   `Helsinki-NLP__opus-mt-en-ru` — это opus-mt. Исходные файлы не тронуты, для Шага 2
   сделаны отдельные NLLB-файлы в `var/data/step2/`. Стоит определиться, какие
   файлы считать каноническими для остальных шагов.
3. **Ручных запросов 10 из 50–100.** Выводы по ним в отчёте предварительные.
4. **`mypy` запускается как `mypy --explicit-package-bases`.** Пустой `code/__init__.py`
   (чужой, не мой) делает `code/` пакетом, и mypy читает `translate.py` под двумя именами.
   Из код-задачи без этого флага `mypy` не запускается — либо удалить файл, либо
   добавить флаг в `pyproject.toml`/CI; флаг пока не прописан ни туда, ни туда.
5. **Базовые метрики не воспроизводятся целиком на CPU за минуту:** индексирование 5000
   функций e5 занимает ~30 мин. Для итераций по Шагу 3 стоит сохранять эмбеддинги
   (`DenseIndex.save`) один раз и переиспользовать — сейчас `run_eval.py` их не пишет.
6. **Метрика `ru_manual` в csv: n=10** — маленькая, но колонка `n_queries` в `baselines.csv`
   показывает это явно.
